**Smart Sprint Planner** — приложение планирования спринтов для [YouTrack](https://www.jetbrains.com/youtrack/) 2024.3+, созданное для команд, где один спринт проходит через несколько функциональных ролей: анализ, тестирование и семь инженерных направлений. Планируйте состав каждой роли, следите за ёмкостью против загрузки, распределяйте задачи по исполнителям и ведите спринт от рабочего черновика до подтверждённой истории — прямо из главного меню YouTrack.

## Как это выглядит

Состав роли — ёмкость против загрузки, плановое/внеплановое включение, прямое редактирование полей YouTrack из таблицы спринта:

## Что вы получаете

**Планирование**

- **9 функциональных ролей** — анализ, тестирование, платформенная разработка, backend, frontend, iOS, Android, fullstack, базы данных. Роли включаются опционально в каждом проекте; универсальная роль `devPlatform` позволяет мапить любой стек (1C, SAP, Salesforce, low-code и т.д.) на собственное custom-поле.
- **Роли-участницы у каждого спринта** — при создании спринта диалог предлагает отметить участвующие роли из активных в проекте; состав фиксируется один раз. Последующая правка ролей в настройках не переписывает существующие спринты: фантомные роли не появляются задним числом, а роли с данными не скрываются.
- **Ролевое поле «Спринт» с записью в задачу** — команда из нескольких ролей в одном проекте может вести спринты в разных полях задачи; вводные показывают один список, пока поле общее, и строку на роль, как только поля разошлись. Отдельный выключатель (по умолчанию выключен) проставляет выбранное значение спринта в каждую активную задачу согласованного состава роли — под правами самого пользователя, с позадачным отчётом. Значение только проставляется и никогда не снимается.
- **Таблицы состава по каждой роли** — назначения с учётом capacity vs. load, overlimit-защита, прямое редактирование полей YouTrack из таблицы спринта.
- **Работа с бэклогом** — предварительная фаза перед планингом: пул задач заказчика видом **«По зонам»** (состояние → роль) или деревом **Эпик ▸ Стори ▸ Таск**, фильтр (query-assist), метки «Перенос»/«Продолжение»/«Нужна оценка»/«Пауза», раскладка задачи в роли спринта одним кликом **«В спринт»** (роли предлагаются по зоне). Незамапленные состояния — в бакет «Прочие» с fail-loud-предупреждением.
- **Три модели планирования** — **«Простая»** (ручная ёмкость роли, исполнители назначаются на Ганте), **«Лёгкая»** (поучастная ёмкость: авторасчёт по формуле или ручной ввод), **«Полная»** (добавляет вкладку «Ёмкость» и берёт утверждённую бизнес-ёмкость спринта по ролям и исполнителям). Параметры расчёта — нормы часов, ставка, процент участия, коэффициенты грейдов — собраны в админ-раздел, который правит только настройщик проекта.
- **Ручной ввод ресурса по исполнителям** — режим `manualPersonalResource` для команд, где team-lead задаёт ёмкость «сверху вниз» фиксированными часами в неделю.
- **Авто-прогноз дат задач** — расчёт плановых дат старта/окончания каждой назначенной задачи от ёмкости исполнителя, производственного календаря и отсутствий (включая частичный день), с дневным капом «полезных часов». Личная очередь задач с мгновенной перепаковкой при переупорядочивании; ручные правки дат живут до явного пересчёта; задачи сверх ёмкости получают честный бейдж «не помещается» вместо фиктивных дат.

**Контроль хода**

- **Gantt-таймлайн по ролям** с фильтрацией по спринтам.
- **История спринтов** — подтверждённые снимки, общий рабочий черновик, персональные черновики у каждого пользователя, восстановление в один клик.
- **Цели спринта** — структурированные цели (название, метрика успеха, ответственный) у каждого спринта, всегда на виду на оверлее стендапа.
- **Ассистент стендапа** — полноэкранный оверлей ежедневного стендапа с per-роль списками задач (Сделано вчера / Делаю сегодня / Заблокировано), таймером и режимом подсветки блокеров; работает напрямую на данных текущего спринта.
- **Дифференцированный учёт трудозатрат (DTA)** — маппинг типа work-item → роль, агрегация факта по ролям обратно в custom-поля задачи, обязательная валидация типа работы, опциональные уведомления о соотношении план/факт.
- **Каскадная агрегация parent ← child** — поля плана и факта контейнерной задачи считаются как сумма прямых детей; контейнеры можно блокировать от прямых списаний work-item.
- **Каскад состояний parent ← min(children)** — State контейнера следует за наименее продвинутым дочерним состоянием: настраиваемый порядок состояний, guard от реоткрытия резолвнутых контейнеров, опциональное минимальное состояние (floor). Переиспользует cascade-иерархию; по умолчанию выключено.

**Отчётность**

- **Оперативная отчётность** — два контура с доступом по группам. **Оперативные (A):** aging с порогами, прогресс к целевым статусам, срез WIP/Done, time-to-market (медианы лид/команда/цикл с нормативами и вычетом пауз), узкое место потока и возвраты, трудозатраты по ролям, план-факт с as-of оценками, ёмкость бэклога, spillover спринтов, velocity команды. **Управленческие (B):** помесячный свод пяти метрик по системам с мульти-линейными графиками, техдолг, «налог на баги», «1000 мелочей». Любой отчёт выгружается в **XLSX или PDF**; долгие прогоны защищены настраиваемым таймаутом с кнопкой «Прервать» и откатом. По умолчанию выключено.
- **Excel-экспорт** для вкладок планирования и истории.

**Управление**

- **Управление релизами** — сборка задач в релизы (вид Релиз / Хотфикс × источник Внутренний / Вендорский) и проведение по шести статусам с предпросмотром и автосменой нативных состояний задач по маппингу. Светофор готовности, состав деревом Эпик ▸ Стори ▸ Таск, фриз состава, патчноуты, экспорт в .txt, необратимый слепок при закрытии и авто-архив старейших закрытых релизов. Права релиз-менеджера / релиз-инженера проверяются на сервере. По умолчанию выключено.
- **Server-side авторизация** на каждом мутирующем эндпоинте через проектные настройки `ssp_settings`; deny-by-default до настройки группы управления настройками.
- **15 языков UI** — чешский, немецкий, английский, испанский, французский, венгерский, итальянский, японский, корейский, нидерландский, польский, португальский, русский, турецкий, китайский (упрощённый). Авто-детект по браузеру, ручное переключение, fallback на английский.

## Установка

Плагин выходит по двум параллельным каналам — версионные бейджи выше всегда показывают текущее состояние каждого:

| Канал | Каденс | Кому подходит |
|---|---|---|
| **[JetBrains Marketplace](https://plugins.jetbrains.com/plugin/31727-smart-sprint-planner)** | Стабильный, JB-ревью | Командам, которым нужны проверенные релизы и встроенный auto-update YouTrack. Каждая выгрузка проходит модерацию JetBrains (1–3 рабочих дня) перед публикацией. |
| **[GitHub Releases](https://github.com/Letsrollamigo/smart-sprint-planner/releases)** | Bleeding-edge | Командам, которым нужны последние возможности сразу и нет проблем с ручной установкой `.zip`. Каждый релиз полностью протестирован в CI (`node --test`: unit + golden), но выходит раньше marketplace-модерации. |

GitHub Releases — авторитетный источник: каждая marketplace-выгрузка собирается из тегированного GitHub-релиза.

### Вариант A — JetBrains Marketplace (рекомендуемый)

1. В YouTrack: **Администрирование → Приложения → Marketplace** → поиск **«Smart Sprint Planner»** → **Установить**.
2. Откройте проект, который хотите планировать, и добавьте виджет **Smart Sprint Planner** на страницу настроек. В разделе **«Доступ и роли»** укажите **группу управления настройками** — это подключает проект к планеру и делает его видимым в главном меню.
3. Откройте **Smart Sprint Planner** из главного меню YouTrack, выберите проект в шапке и начинайте планировать. Пока группа управления настройками не настроена, все мутации запрещены.

YouTrack автоматически обновляет плагин по мере публикации новых marketplace-версий.

### Вариант Б — GitHub Release

1. Скачайте свежий `Smart-Sprint-Planner-vX.Y.Z.zip` со страницы [Releases](https://github.com/Letsrollamigo/smart-sprint-planner/releases).
2. В YouTrack: **Настройки проекта → Приложения → Установить из файла** → загрузите zip.
3. Те же шаги по виджету и настройкам, что выше.

Подробная конфигурация — в [USER-GUIDE.ru.md](USER-GUIDE.ru.md). Взгляд team-lead'а / Scrum master'а на то, как плагин ложится на Scrum-церемонии и capacity planning, — в [METHODOLOGY-GUIDE.ru.md](METHODOLOGY-GUIDE.ru.md).

## Как это устроено

<p align="center">
  <img src="../assets/readme/workflow.svg" width="100%"
       alt="Два виджета — планер главного меню и страница настроек проекта — разделяют одно ядро логики backend-core.js, которое хранит всё в extension properties проекта под namespace ssp. Каждый мутирующий эндпоинт авторизуется на сервере.">
</p>

- **`ssp-main-global` (MAIN_MENU_ITEM)** — полный планер в главном меню YouTrack: дашборд «рельс + пейн» с выбором проекта и деревом навигации (Параметры спринта / Планирование / Работа с бэклогом / Гант / История). Планирование — два уровня: **«Аллокация общего ресурса»** (accordion-карточки ролей) и **«Распределение по исполнителям»** (видно при модели «Лёгкая»; при «Простой» исполнители назначаются на диаграмме Ганта).
- **`ssp-main` (PROJECT_SETTINGS)** — страница настроек проекта: роли, поля, режимы и **группа управления настройками**. Указание группы «подключает» проект: он появляется в планере главного меню для всех, у кого есть доступ к проекту в YouTrack. До этого проект в меню не виден, а его настройки — только на просмотр.

## Сборка из исходников

```bash
git clone https://github.com/Letsrollamigo/smart-sprint-planner.git
cd smart-sprint-planner
npm ci
npm run build:check    # syntax-проверка bundle и workflow-файлов
npm test               # unit + golden (Node test runner, jsdom — без браузера и YouTrack)
```

Требования: Node.js 20+. Инстанс YouTrack 2024.3+ нужен только для **ручной** end-to-end проверки — см. [docs/LOCAL_YT.md](../docs/LOCAL_YT.md); автоматический набор YouTrack не требует. Гайд контрибьютора: [CONTRIBUTING.ru.md](CONTRIBUTING.ru.md).

## Совместимость

- **YouTrack**: 2024.3 и новее (используется современный app-widget API и `extensionPoint: PROJECT_SETTINGS`).
- **Браузеры**: любой evergreen-браузер, поддерживаемый самим YouTrack.
- **Хранилище**: extension properties под namespace'ом `ssp_*`; cross-tab синхронизация через `localStorage`-сигнал `ssp:wc-touched:*`.
