## [2.2.4] — 2026-06-04

> **Починка кнопки обновления Stand-up (попутно к #35).**

### Исправлено

- **Кнопка «Обновить» на вкладке Stand-up** теперь работает. Раньше слался неверный запрос (контракт эндпоинта не совпадал) — обновление молча не срабатывало (с момента full-rebuild). ## [2.2.3] — 2026-06-04

> **Универсальная кнопка «Обновить из задачи» (#35).**

### Добавлено

- **Единая кнопка «Обновить из задачи»** на обеих вкладках планирования и в Ганте. Один батч-запрос тянет полный срез задачи (оценка, факт, состояние, приоритет, система, исполнитель) и обновляет обе вкладки и Гант сразу.
- **Защита несохранённых правок.** При расхождении локальных данных с YouTrack показывается сводка с выбором: «Обновить всё из YouTrack» / «Сохранить мои правки» / «Показать различия» (diff по оценке/факту/исполнителю).
- **Блокировка обновления**, пока открыт незакоммиченный редактор ячейки; обновление доступно только для активного спринта.

### Изменено

- Три прежних точки обновления (по роли, по исполнителям, Гант) объединены в единый путь `refreshFromYouTrack`. Метка кнопки консолидирована в ключ `btnRefreshFromTask`.

## [2.2.0] — 2026-06-03

> **Понятный ввод значений периода (#34).**

### Изменено

- **Голое число при вводе времени теперь трактуется как часы** (раньше — минуты): ввод «16» = 16 ч. Затрагивает все поля периода (ресурс/ёмкость, оценка, аллокация).
- **Суффиксы единиц учитывают язык интерфейса.** Парсер понимает обозначения часов/минут активной локали (а также латинские `h`/`m` и русские `ч`/`м`); это снимает рассинхрон ввода и отображения для всех 15 языков (в т.ч. турецкого, где «d» = минута).
- **Поля периода авто-форматируются при потере фокуса** к каноничному виду «часы+минуты»: «16» → «16ч», «90м» → «1ч 30м».
- **Единый placeholder-подсказчик** «напр. 16ч / 90м» на всех полях ввода периода.

### Удалено

- **Ввод дней/недель убран** в пользу единых часов/минут (вывод их и так не показывал). Ранее принимавшиеся «5д»/«2н» теперь трактуются как часы.

## [2.1.46] — 2026-06-03

> **Локализация значений приоритета/состояния по языку виджета (B7) + режим планирования с превышением лимитов (#38).**

### Исправлено

- **Значения приоритета и состояния задач отображаются на языке интерфейса виджета (B7).** YouTrack отдаёт значения enum-полей (Приоритет, Состояние, Сквозной приоритет) в локали сервера, поэтому при английском (и других не-русских) языке виджета они всё равно показывались по-русски. Теперь для отображения добавлен locale-aware резолвер: на русском поведение прежнее, на остальных языках стандартные значения показываются на канонических английских названиях. Кастомные значения без канонического перевода показываются как есть. Затронуто только отображение (таблица планирования, история, экспорт в Excel, диаграмма Ганта); внутренняя логика (агрегация по типам ЧЧ, снимки истории, сортировка, диаграмма Ганта) использует исходные значения и не изменена.

### Добавлено

- **Режим «Разрешить планирование с превышением лимитов» (#38).** Новый флажок в настройках («Режимы планирования»). При включении: валидация не блокируется и overlimit-окно не показывается, когда суммарная аллокация роли превышает её ресурс; отрицательные остатки по-прежнему отображаются красным как индикатор (обнаружение превышения сохраняется — меняется только реакция). В шапке виджета добавлен чип статуса этого режима. Локализация — все 15 языков.

## [2.1.44] — 2026-06-02

> **Исправление детектора превышения ресурса роли (B13).**

### Исправлено

- **Детектор превышения теперь учитывает суммарную аллокацию роли.** Раньше превышение проверялось только по каждой задаче отдельно (аллокация задачи > её дельты «оценка − факт»); при пустых оценках дельта равнялась нулю, и превышение не обнаруживалось, хотя остаток роли уже был отрицательным. Добавлена агрегатная проверка: суммарная аллокация активных задач против ресурса роли (тот же расчёт, что красит карточку «Остатки» красным). Кнопка «Валидировать» теперь блокируется, а для согласованных/распределённых ролей всплывает overlimit-окно даже когда оценки задач пусты.

## [2.1.43] — 2026-06-02

> **Завершение де-гибридизации (#32, фаза 6, ч.2)** — всплывающие уведомления (toast) переведены на настоящий Ring UI (`alertService` + `Alert`), визуальный стиль унифицирован со всеми модалками. Де-гибридизация #32 завершена.

### Изменено

- **Тосты переведены на Ring `alertService`.** Custom-DOM тостов заменён настоящими Ring `Alert`. Контракт `toast(msg, type)` и `toastApi.{info,warn,error,success,dismissAll}` сохранён 1:1: маппинг типов → Ring (info→message, warn→warning, error→error, success→successMessage), длительности по типам сохранены (info/success 4 с, warn 6 с, error — persistent), очередь ограничена 3 (вытесняется старейший не-error). `alertService` добавлен в vendor-бандл; CSS Ring Alert добавлен в curated-сабсет Ring.
- **Позиционирование тостов в auto-grow iframe.** Ring рендерит контейнер алертов в `document.body` как `position:fixed` (правый нижний угол) — в auto-grow виджет-iframe YouTrack это уходит за пределы видимой части (та же проблема, что решал custom-тост). Контейнер переякорен на `position:absolute` с JS-вычислением top относительно последнего клика (гарантия видимой области). Legacy DOM-стак тостов сохранён как fallback, если vendor-бандл недоступен.

## [2.1.16] — 2026-06-01

> **Де-гибридизация модалок Ring UI, фаза 2 (#32)** — ещё 5 модалок переведены на настоящий React, плюс исправлены два пред-существующих бага рабочих копий (всплыли, когда модалки стало возможно реально вызвать).

### Изменено

- **Модалки рабочих копий, переназначения и результата спринта на настоящем Ring UI.** Пять модалок — конфликт версий, «открыто в другой вкладке», отмена правки рабочей копии, переназначение задачи, подтверждение результата спринта — теперь рендерят настоящий React-контент в Ring Dialog через `openModal(spec)`, без DOM-трансплантации. Переназначение (`<select>`) и подтверждение результата (radio исхода + заметка ретро) — bespoke React-компоненты; диалог результата сохраняет контракт `Promise<{goalOutcome, goalRetroNote}|null>`. Блокирующая модалка «открыто в другой вкладке» остаётся незакрываемой (Escape отключён).
- **Escape модалок укреплён.** Escape надёжно закрывает любую неблокирующую модалку через слушатель на уровне foundation, независимо от того, на каком контроле фокус (собственный обработчик Ring не срабатывал, когда фокус на radio/textarea).

### Исправлено

- **Рабочие копии больше не «коммитятся» сразу при открытии.** Открытие записи истории на правку создавало рабочую копию, которую тут же коммитил и удалял пассивный авто-снапшот после сохранения sprint-data, — поэтому кнопка «Отменить правку» не появлялась. Авто-снапшот теперь пропускается при активной рабочей копии (правки идут в черновик; commit — только явный).
- **Рабочие копии и черновики снова сохраняются между перезагрузками.** Extension properties `ssp_workdrafts` и `ssp_drafts` не были задекларированы в `entity-extensions.json`, поэтому YouTrack молча терял записи (POST возвращал OK, следующий GET — пусто). Оба свойства задекларированы. Этот баг маскировался авто-коммитом выше.

## [2.1.15] — 2026-06-01

> **Де-гибридизация модалок Ring UI, фаза 1 (#32)** — confirm-модалки теперь рендерятся через настоящий React вместо DOM-обёртки, плюс два фикса взаимодействия.

### Изменено

- **Confirm-модалки на настоящем Ring UI.** Девять подтверждающих модалок (очистка черновика, очистка/удаление истории спринтов, завершение спринта, очистка состава роли, очистка/удаление исполнителей, превышение ресурса роли, закрытие рабочей копии) переведены с DOM-обёртки (трансплантация vanilla-DOM в Ring Dialog) на настоящий React-рендеринг контента через декларативный API `openModal(spec)`. Единый внешний вид, корректная ширина диалога, без артефактов разделителей.

### Исправлено

- **Сохранение состава ролей после синхронизации состояния из YouTrack.** После обновления состояния задачи из YouTrack (бейдж состояния на Ганте / кнопка «Обновить») сохранение или валидация спринта по этой роли могли падать с ошибкой структуры данных (`invalid_role_items_structure`). Бэкенд-валидатор теперь принимает поля состояния `stateLocalized`, `stateColor`, `stateFieldId` в составе задачи (добавлены в whitelist — релиз 2.1.14 #20 писал их во фронтенде, но whitelist не был расширен).
- **Реакция на первый клик в таблицах Ring Table.** Кнопки удаления (корзинки) задачи и исполнителя, а также ячейки быстрой правки (состояние/приоритет/система) теперь срабатывают с первого клика — раньше требовался второй. Причина: Ring Table на `mousedown` пересоздаёт строку, из-за чего браузер не генерировал событие `click` на первом клике; обработчики переведены на `mousedown`.

## [2.1.14] — 2026-05-30

> **Состояние задачи на диаграмме Ганта (#20)** — бейдж текущего State с цветами YouTrack, дата последнего перехода и предыдущее состояние. Изменений схемы нет.

### Добавлено

- **Бейдж состояния задачи.** В левой ячейке-метке строки Ганта (под именем исполнителя) — pill текущего State в родных цветах YouTrack (фон/текст из палитры состояния), рядом дата перехода «с {дата}».
- **Предыдущее состояние.** Отдельной строкой «← было «{state}» · N дн. назад» с цветной точкой прошлого состояния. История подтягивается из YouTrack Activities API на стороне виджета (бэкенд не имеет доступа к activity-логу); прогрессивный рендер — бейдж рисуется сразу, история дозагружается асинхронно.
- **Локализация.** 6 новых строк UI переведены на все 15 поддерживаемых локалей.

### Изменено

- **Цвет полосы Ганта** теперь отражает состояние задачи (родная палитра YouTrack), а не исполнителя. Fallback — нейтральный серый при отсутствии состояния или цвета.
- **Кнопка «Обновить из задач» → «Обновить».** Две кнопки на Ганте слиты в одну: тянет из YouTrack исполнителя и состояние, затем перезагружает историю переходов. Бэкенд-endpoint `refresh-assignees` теперь возвращает и State (имя + цвет).

### Удалено

## [2.1.11] — 2026-05-28

> **Финальное исправление B10** — стабильное single-click переключение чекбоксов в production с Ring Table + React Checkbox. Без schema-изменений. 419 тестов проходят.

### Исправлено

- **[B10 — финал] Состояние чекбокса в «Подборе задач» сбрасывалось обратно в «0» сразу после single-click.** Capture-listener из v2.1.10 диспатчил `host.dispatchEvent(new Event('change'))` для делегирования `_selectedIds`. - **Новый необязательный dropdown «ID задачи во внешней системе»** в секции настроек «Прочие поля». Выбирает string-поле YouTrack, в котором хранится ID тикета во внешней системе (Service Desk, Jira, 1C, SAP, …).
- **Read-only колонка «Внешний ID»** в трёх таблицах: состав роли, распределение по людям, история. **Позиция колонки: 2-я, сразу после ссылки на задачу** (правка UX по фидбэку в v1.8.1).
- **Детект URL:** значения вида `https?://…` рендерятся как кликабельные `<a>` (открываются в новой вкладке); обычные строки усекаются до `12em` с полным значением в hover-tooltip.
- **Автозаполнение** при подборе / refresh — значение читается из YouTrack при добавлении задач или обновлении оценок. Фиксируется в confirmed history-snapshot'ах (историческая точность сохранена).
- **Сортировка по «Внешний ID»** — добавлена в цикл сортировки (`off → xpriority → priority → id → system → externalTicketId`), лексикографическая; пустые значения в конце.
- **Первая live-валидация item-level schema migration** — `ALLOWED_ITEM_KEYS` расширен `externalTicketId` (опциональный, ≤ 1000 символов; лимит поднят с изначальных 200 после того как реальные URL не пролезали). `SCHEMA_MIGRATIONS` registry содержит шаг v1.7.0 → v1.8.0 (no-op, additive).
- **i18n × 15 локалей** для фичи (4 ключа: `fldExternalTicketId`, `fldExternalTicketIdOptional`, `hintExternalTicketId`, `thExternalTicketId`).

### Добавлено — UX-архитектура (v1.8.1)
- **Per-role бейджи статуса в шапке виджета.** Заменяет агрегированный одиночный бейдж (который показывал `min(STATUS_RANK)` всех ролей и висел «Черновиком» когда хотя бы одна роль ещё не валидирована, независимо от остальных). Теперь каждая активная роль показывает свой статус с префиксом-именем роли.
- **Per-role бейдж статуса на карточке роли** — читает из `_history[<sprintId>_<roleKey>].status` вместо глобального `_sprint.status`. Валидация одной роли больше не меняет индикатор статуса у остальных.
- **Settings → «Прочие поля» визуально разделены** на «Обязательные» (Приоритет, Состояние — помечены красной `*`) и «Необязательные» (Сквозной приоритет, Система, ID задачи во внешней системе, Поле спринта, Версия — у каждого приглушённый суффикс «(необязательно)»). 3 новых i18n-ключа × 15 локалей = 45 строк (`cardOtherFieldsRequired`, `cardOtherFieldsOptional`, `fldOptionalSuffix`).
- **Необязательные колонки скрываются если не настроены** — колонки XPriority и Система пропадают из всех 3 таблиц (состав, люди, история) когда соответствующее YT-поле в маппинге пустое. Симметрично поведению External ID.
- **Soft warning при save настроек** если Обязательные поля (Приоритет/Состояние) не заданы — неблокирующий warn-toast через 400 мс после success-toast перечисляет какие поля рекомендуется задать. 1 новый i18n-ключ × 15 локалей.
- **Спойлер в Истории теперь показывает имя спринта + роль в свёрнутом виде** — раньше они были только в развёрнутом теле, и было сложно идентифицировать к какому спринту/роли относится запись. 2 новых i18n-ключа × 15 локалей (`histSpoilerName`, `histSpoilerRole`).
- **«Перейти в Людей» из карточки роли передаёт контекст роли** — клик на кнопке в карточке Аналитики открывает вкладку «Люди» с предвыбранной Аналитикой, независимо от того какая роль была там последней. Раньше использовался `safeLs.lastActiveRole` (устаревший).
- **Выбор роли на вкладке «Люди» визуально выделен** — акцент-бордюр слева, иконка 👥, uppercase bold-label, увеличенный select с primary-color бордюром и focus-ring. Какая роль редактируется — больше не пропустить.
- **Бейджи статуса в шапке корректно переносятся** при 2–9 активных ролях — явный `flex: 0 0 100%` + `flex-wrap: wrap` + компактный шрифт (10 px, `padding 2px 6px`) обеспечивает что блок бейджей уходит на свою строку под селектором спринта и переносится по строкам без горизонтального скролла, даже на узких экранах.
- **Inline-error подсветка при save параметров спринта** (v1.8.2) — gate на имя и даты. При failure валидации проблемное поле получает красный бордюр + `field-err` текст под ним + `scrollIntoView({behavior:'smooth', block:'center'})`. Toast остаётся дублирующим сигналом, но больше не единственный — релевантно когда YT-iframe scroll-позиция выталкивает fixed-position toast за пределы viewport главного окна.

### Исправлено
- **`saveRoleHistorySnapshot` не копировал `externalTicketId`** в `snap.items` — значения были живые на items, но не доходили до истории. Корень провала приёмки v1.8.0 («тикет ID не записался в историю»). Поле теперь явно копируется при непустом значении.
- **`invalid_history_structure` при auto-snapshot** после валидации спринта — вызвано протухшей записью `revisions[i].level = 'NONE'` в `_history` от ранних commit'ов working-copy без значимых изменений. `'NONE'` возвращался из `computeRequiredRevalidationLevel`, но отсутствовал в backend whitelist `ALLOWED_REVISION_LEVELS`. Починено с двух сторон: backend whitelist теперь принимает `'NONE'` (backward-compat для существующих отравленных данных); frontend `_commitWorkingCopy` пропускает запись revision-entry если `level === 'NONE'` (forward fix — новые записи без неё).
- **`renderWidgetHeader` не вызывался после commit working-copy** — бейдж в шапке висел на старом статусе после редактирования исторического спринта через «Открыть на правку» → валидация. Добавлен явный вызов `renderWidgetHeader()` в `_commitWorkingCopy.then(...)`.
- **Кнопка «+ Новый спринт» — селектор текущего спринта не обновлялся** на свежесозданный черновик. Починено синхронизацией `_currentSprintId = _sprint.sprintId` в `doNewSprint` до API-roundtrip + persist в `ui` draft.
- **Сохранение параметров нового спринта** — селектор шапки не обновлялся до перезахода на вкладку. Добавлены sync `_currentSprintId` + `renderWidgetHeader()` в `doSaveRoleHeader` success-ветке.
- **Лимит External ID был слишком строгим** — изначальный 200-символьный лимит отклонял реальные URL (например, `https://tracker.example.com/t#id104909392` и длиннее). Теперь использует стандартный `strFields`-лимит 1000 символов.
- **Запись `SCHEMA_MIGRATIONS` для v1.8.0** — добавлен явный `{from:'1.7.0', to:'1.8.0', migrate:noop}` для audit-trail в `migrationLog` каждого мигрированного snapshot'а. Первая item-level миграция в registry (ранее только settings-level).
- **Диагностика ошибок POST history** — когда `validateHistoryForWrite` отвергает payload, в ответе теперь конкретное поле/индекс с ошибкой (например `invalid_history_structure: revisions[0].level_invalid:NONE (record[5])`) вместо непрозрачного `invalid_history_structure`. Сделало возможным root-cause hunt бага с `NONE`.

### Изменено
- **Подсказка под dropdown'ом «ID задачи во внешней системе» удалена** — label + суффикс «(необязательно)» самодостаточны.
- **Цикл сортировки расширен** с 5 до 6 позиций — добавлен `externalTicketId`.
- **Cache-buster bump'ы версии** (v1.8.1, v1.8.2) — многократные in-place переустановки v1.8.0 заставляли YouTrack держать закешированные `widgets/main/main.js` и `widgets/main/index.html`. Каждый bump форсирует свежий asset hash.
- **`validateItem` / `ALLOWED_ITEM_KEYS`** добавлены в CommonJS test-export shim — требуется новыми unit-тестами.
- **`snapshot-migration.test.js`** обновлён: `SCHEMA_MIGRATIONS.length === 2` (было 1).

### Безопасность
- Все значения `externalTicketId` проходят через `esc()` на каждом пути рендеринга. URL-значения проходят через `safeUrl()` перед вставкой в `href` — аналогично обработке `item.url`.
- Поле read-only на клиенте. Заполнение только через существующий путь pick / refresh через API. Whitelist-гарды исключают запись произвольных ключей.

### Обратная совместимость
- **Breaking schema-изменений нет.** `externalTicketId` опциональный на каждом item; sprints / history / working-drafts, записанные в v1.6.x или v1.7.x, читаются v1.8.2 без изменений.
- **Записи `level='NONE'`** от pre-fix commit'ов working-copy теперь принимаются backend whitelist'ом. Они перестают накапливаться на новых commit'ах, но старые сохраняются и проходят POST-валидацию.
- **Rollback** (мягкий, per-project): очистить dropdown «ID задачи во внешней системе» в Settings → Save. Колонка пропадает; сохранённые значения остаются в snapshot'ах. **Rollback** (жёсткий, переустановка v1.7.1): backend v1.7.1 молча игнорирует ключи `externalTicketId` через tolerant ForRead (`WARN_UNKNOWN_KEY` в `migrationLog`).

- **185 unit-тестов** (было 169 в v1.7.1).
- **Новый файл тестов** `tests/unit/external-ticket-id.test.js` — 8 кейсов (наличие в whitelist, граничные значения, отказ на неправильных типах, приём URL, обратная совместимость).

## [1.7.1] — 2026-05-15

### Добавлено (Переводы)

Обернули `#stateRollupRescanBtn` в `<span>` с title-атрибутом + `pointer-events: none` на самой кнопке — tooltip теперь надёжно появляется при hover с текстом «Coming in a future release» / «Появится в одном из следующих релизов» (формулировка не привязана к конкретной версии — реализация rescan в backlog'е без фиксированной target-версии).
