# 06. Прочие поля

**Обязательно в части «Основные».** Здесь планер узнаёт, какое поле в вашем проекте отвечает за приоритет и какое — за состояние задачи.

## Где

**Настройки проекта → Приложения → Smart Sprint Planner → ПЛАНИРОВАНИЕ → «Прочие поля»**.

## Основные

| Поле | Зачем |
|---|---|
| **Приоритет** | колонка приоритета в таблицах, сортировка задач |
| **Состояние** | состояние задачи в таблицах, на Ганте, в стендапе, в зонах бэклога |

Если поля не выбраны, планер возьмёт поля с именами `Priority` и `State` — стандартные поля YouTrack. Сохранение при этом не блокируется, но показывается предупреждение.

Лучше выбрать явно: в проектах с переименованными полями догадка не сработает, и половина экранов останется без состояний.

## Необязательные

| Поле | Что даёт | Нужно ли |
|---|---|---|
| **Сквозной приоритет** | вторая шкала приоритета — когда важность задачи в масштабе портфеля отличается от важности внутри проекта | по желанию |
| **Система** | колонка «Система» в таблицах и разрез в отчётах | удобно, если подсистем много |
| **ID задачи во внешней системе** | номер задачи в смежном трекере | если ведёте задачи в двух системах |
| **Поле спринта** | если в проекте уже есть собственное поле спринта, планер может его заполнять | по желанию |
| **Версия** | связка задач с версией | по желанию |
| **Тип** | тип задачи; используется фильтром бэклога, каскадом оценок и отчётами | нужно для глав [11](11-backlog.md), [14](14-cascade.md) и отчётности |

Пустое значение — нормальный вариант: планер просто не покажет соответствующую колонку.

## На что влияет «Система»

Это самое полезное из необязательных полей. Колонка «Система» появляется в составе роли, в бэклоге и в распределении по исполнителям, а в отчётности по ней строится целый разрез — «Свод» показывает помесячный тренд метрик **по системам**.

Если в проекте одна система, поле можно не заполнять. Если их пять — заполните: без него отчёты контура B теряют половину смысла.

## На что влияет «Тип»

Поле типа задачи используется в трёх местах:

- **фильтр типов бэклога** — какие типы вообще попадают в пул (глава [11](11-backlog.md));
- **каскад оценок** — по типу определяются уровни иерархии: что считать эпиком, а что историей (глава [14](14-cascade.md));
- **отчёты контура B** — «Техдолг» и «Налог на баги» отделяют баги и техдолг от фич именно по типу.

## Шаги

1. В блоке «Основные» выберите поле приоритета и поле состояния.
2. В блоке «Необязательные» выберите то, что действительно пригодится.
3. Нажмите **«Сохранить настройки»**.
