# 19. Отчётность: настройка

**Необязательно.** Модуль добавляет в рельс два раздела отчётов: **Оперативные (A)** и **Управленческие (B)**. Что показывает каждый отчёт — в документе [«Отчётность»](../03-reporting/).

## Где

**Настройки проекта → Приложения → Smart Sprint Planner → АДМИНИСТРИРОВАНИЕ → «Отчётность»**.

## Два условия доступа

Отчёты видны при совпадении двух условий:

1. модуль **включён** в этом проекте — здесь;
2. вы состоите в группе, которой в [матрице прав](09-permissions.md) отмечен нужный **контур**.

Одного включения мало: без отметки в матрице отчёты останутся видны только менеджеру настроек.

## Что настраивается

### Поток и целевые статусы

| Настройка | Что задаёт |
|---|---|
| **Состояния потока** | упорядоченный список состояний — по нему строятся отчёты «Поток» и «Прогресс» |
| **Целевые статусы** | что считается «доехало»: обычно `Ready for Release`, `Released`, `Done` |
| **Подписи статусов** | человеческие названия для отчётов: `Released` → «Отгружено» |
| **Политика терминального перехода** | считать по первому попаданию в терминальное состояние или по последнему |

### Пороги и нормы

| Настройка | Что задаёт |
|---|---|
| **Пороги Aging** | сколько дней в состоянии — «жёлтая» зона, сколько — «красная»; задаётся на каждое состояние |
| **Якоря TTM** | от какого состояния до какого мерить Lead, Team и Cycle |
| **Нормы TTM** | целевые значения Lead и Team в днях |
| **Возрастные полосы Spillover** | сколько спринтов подряд задача переносится, чтобы стать «тёплой» и «горячей» |
| **Окно Velocity** | сколько последних спринтов усреднять |
| **Месячная ёмкость роли** | ориентир для отчёта «Бэклог в ЧЧ» |

### Прочее

| Настройка | Что задаёт |
|---|---|
| **Маркеры пауз** | состояния и теги, время в которых вычитается из цикла |
| **Типы связей для отчётов** | какие связи считать «этот баг про эту фичу» — нужно отчёту «Налог на баги» |
| **Показывать систему** | добавить разрез по системе в таблицы отчётов |
| **Таймаут отчёта**, **Потолок среза** | ограничители тяжёлых выборок |

## Что задать обязательно

Отчёты снисходительны к пустым настройкам, но три из них без значения ломают конкретные отчёты:

- **Целевые статусы** — без них «Прогресс» не знает, куда считать переходы;
- **Якоря TTM** — без них отчёт TTM не строится;
- **Типы связей для отчётов** — без них «Налог на баги» отказывается считать.

Остальное имеет разумные значения по умолчанию.

## Нагрузка

Отчёты строят выборки по истории задач и создают заметную нагрузку на YouTrack. Ограничители **«Таймаут отчёта»** и **«Потолок среза»** нужны именно для этого: они не дают одному отчёту занять инстанс.

На больших проектах имеет смысл сузить период отчёта, а не поднимать потолок.
