# 11. Работа с бэклогом: зоны пайплайна

**Необязательно.** Модуль превращает список задач проекта в очередь работы, разложенную по стадиям и ролям.

## Где

**Настройки проекта → Приложения → Smart Sprint Planner → АДМИНИСТРИРОВАНИЕ → «Бэклог»**.

## Что настраивается

| Настройка | Что задаёт |
|---|---|
| **Стартовые состояния** | какие состояния считаются «работа ещё не начиналась» — из них собирается пул заказчика |
| **Зоны** | упорядоченный список: состояние → роль (или несколько ролей) |
| **Фильтр типов** | какие типы задач попадают в пул |
| **Состояния паузы** | состояния, в которых задача формально в работе, но команда её не двигает |
| **Теги паузы** | то же, но по тегу задачи |

## Зоны

Зона — это пара «состояние пайплайна → чья это работа». Порядок зон в списке задаёт порядок секций на экране бэклога, и он должен повторять реальный поток.

Пример:

| Состояние | Роль |
|---|---|
| Analysis | анализ |
| Analysis Review | анализ |
| Development | платформенная разработка |
| Code Review | платформенная разработка |
| Testing | тестирование |
| Business Test | тестирование |

Одно состояние может принадлежать нескольким ролям — планер это допускает.

## Фильтр типов

Ограничивает пул типами задач: обычно `Feature`, `Bug`, `Tech Debt`. Эпики и истории в пул не пускают, чтобы очередь состояла из работы, а не из контейнеров.

⚠️ **Фильтр действует и на дерево.** Вид «Дерево» строит иерархию по тем же задачам, что попали в пул. Если ребёнок эпика имеет тип вне фильтра, в дереве его не будет, и эпик покажется пустым.

## Паузы

Пауза — состояние или тег, означающие «ждём не нас»: поставщика, ответа заказчика, чужого релиза. Планер выделяет такие задачи отдельно, а отчётность вычитает паузы из времени цикла — иначе ожидание вендора попадает в метрику скорости команды.

## Незамапленные состояния

Планер сверяет список состояний проекта со своей раскладкой и показывает оранжевую полосу, если какое-то состояние не отнесено ни к зонам, ни к стартовым, ни к паузам и не помечено в YouTrack как решённое.

Полосу стоит закрыть до того, как модулем начнёт пользоваться команда: задачи в незамапленном состоянии просто не видны на экране бэклога.
