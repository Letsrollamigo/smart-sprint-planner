# 14. Каскад оценок

**Необязательно.** Модуль складывает оценки и факт детей в родителя: эпик показывает сумму своих историй, история — сумму подзадач.

## Где

**Настройки проекта → Приложения → Smart Sprint Planner → АДМИНИСТРИРОВАНИЕ → «Каскад оценок»**.

## Что настраивается

| Настройка | Что задаёт |
|---|---|
| **Включить каскад** | главный переключатель |
| **Поле типа** | по какому полю определять уровень иерархии |
| **Уровень 2** | значения типа, считающиеся «историей» |
| **Уровень 3** | значения типа, считающиеся «эпиком» |
| **Тег защиты ручной оценки** | тег, при котором родитель из агрегации исключается |
| **Запретить списания на контейнерах** | не давать списывать время на родителей |

## Два уровня, не больше

Каскад поддерживает **два уровня** иерархии: эпик ← история ← подзадача. Глубже он не идёт — намеренно: глубокие деревья превращают агрегацию в источник расхождений, которые никто не может проверить.

## Тип связи «родитель — ребёнок»

Каскад ходит по связям иерархии. Какие типы связей считать иерархией, задаётся не здесь, а в разделе [«Связи задач»](16-links.md) — там таблица «тип связи × роль».

## Тег защиты ручной оценки

Иногда у родителя есть собственная осмысленная оценка, которую сумма детей испортит: например эпик оценили экспертно, а детей завели не всех.

Поставьте на такой родитель тег из настройки — и каскад его пропустит.

## Запрет списаний на контейнерах

Отдельное воркфлоу-правило: не даёт списывать время на задачи уровней 2 и 3. Смысл в том, что часы должны попадать на конкретную работу, а не на контейнер, — иначе сумма детей и собственные часы родителя начинают спорить.

Включать стоит вместе с каскадом: по отдельности они противоречат друг другу.
