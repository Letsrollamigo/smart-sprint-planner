# 14. Пришли из Jira: словарь терминов

Если команда раньше работала в Jira, привычные слова ищутся не там и не под теми именами. Эта глава — словарь: термин Jira → как это называется в планере → в какой главе описано. В конце — что планер намеренно делает иначе и чего в нём нет.

Планер не заменяет YouTrack. Задачи, состояния, учёт времени, доски остаются в трекере; планер — слой планирования спринта **по ролям** поверх него.

## Планирование спринта

| В Jira | В планере | Где описано |
|---|---|---|
| Sprint | **Спринт** — название, период, цель, роли-участницы. Состав ведётся отдельно на каждую роль | 02 |
| Поле «Sprint» в задаче | **Поле спринта** проекта — общее или своё у каждой роли. Планер читает его, а по отдельному выключателю записывает выбранное значение в задачи согласованного состава | 02; [«Внедрение»](../02-setup/), глава 05 |
| Backlog | **Работа с бэклогом** — пул задач по зонам «состояние → роль» или деревом; кнопка «положить в спринт» раскладывает задачу по ролям | 04 |
| Team | **Роли** — виды работы (анализ, разработка, тестирование…), а не команды и не должности. Люди приходят в роль из групп YouTrack | 05, 06; [«Внедрение»](../02-setup/), глава 05 |
| Team capacity | **Ёмкость** — ресурс роли в часах: вручную, по формуле «норма × КПЕ × ставка × участие» или из утверждённой ёмкости спринта с календарём и отсутствиями | 03, 05 |
| Assignee | **Исполнитель** — распределение задач роли по людям, персональный остаток, автопрогноз дат | 07 |
| Sprint Goal | **Цель спринта** — заголовок, метрика успеха, владелец; при закрытии планер спрашивает результат по цели | 02 |
| Start / Complete Sprint | **Стадии роли**: черновик → согласован → распределён → закрыт. Кнопка «Завершить спринт» (или «Завершить все роли») кладёт снимок состава в историю | 12, 10 |
| Roadmap, Timeline | **Диаграмма Ганта** по ролям — сроки задач, зависимости стрелками, масштаб | 09 |
| Dashboard | **Главное меню** планера — вход по всем проектам, вне вкладки проекта | 01 |

## Оценки и время

| В Jira | В планере | Где описано |
|---|---|---|
| Story Points | **Нет.** Оценка — в часах, в отдельном period-поле у каждой роли («Поле оценки» в таблице ролей) | 06; [«Внедрение»](../02-setup/), глава 05 |
| Original Estimate | **Оценка роли** — то же period-поле. Планер читает его из задачи и не хранит | 06 |
| Time Spent, Log work | **Факт роли** — рабочие записи YouTrack, разнесённые по ролям через тип работы (дифференцированный учёт трудозатрат) | 06; [«Внедрение»](../02-setup/), глава 13 |
| Remaining Estimate | **Остаток** — оценка минус факт. Если у задачи указана ручная **аллокация**, в расчёт идёт она | 05, 06 |
| Velocity | **Velocity команды** — отчёт A11: закрытые часы по ролям за последние спринты и тренд. Считается по снимкам истории, отдельно на каждую роль | [Отчётность](../03-reporting/), глава 05 |
| Burndown | **Нет.** Ход спринта смотрят по остаткам роли, на стендапе и в отчёте «Прогресс» | 05, 08; [Отчётность](../03-reporting/), глава 02 |

## Структура задач

| В Jira | В планере | Где описано |
|---|---|---|
| Epic ▸ Story ▸ Sub-task | **Иерархия по связи «подзадача»** — дерево бэклога, каскад план/факт «родитель ← дети», состояние родителя по наименее продвинутому ребёнку | 04; [«Внедрение»](../02-setup/), главы 14–16 |
| Issue links (blocks, is blocked by) | **Связи задач** — набор формулировок настраивается; зависимости рисуются стрелками на Ганте | 09; [«Внедрение»](../02-setup/), глава 16 |
| Components | Поле **«Система»** — колонка в таблицах состава и распределения | 06; [«Внедрение»](../02-setup/), глава 06 |
| Fix Version, Release | **Релизы** — вид (релиз или хотфикс), состав задач, статусы с синхронизацией состояний задач, светофор готовности | 11 |

## Ход спринта

| В Jira | В планере | Где описано |
|---|---|---|
| Daily stand-up | **Стендап** — полноэкранный режим: по ролям «сделано вчера / сегодня / блокеры», таймер | 08 |
| Sprint report | **История спринтов** — снимок состава каждой роли, выгрузка в Excel и JSON, возврат к правке | 10 |
| Перенос незакрытых задач при Complete Sprint | Автоматического переноса нет. В бэклоге следующего спринта такие задачи помечены **«Перенос»** или **«Продолжение»**; что взять дальше — решает команда на планировании | 04 |
| Retrospective | **Результат по цели** — при закрытии спринта планер просит подтвердить, достигнута ли цель, и принимает заметку ретроспективы | 02 |

## Что мы намеренно делаем иначе

1. **Часы вместо story points.** Планер сравнивает загрузку роли с её ресурсом в часах. Story points одной командой на всех складываются в одно ведро и прячут, что тестирование — узкое место, а разработка простаивает. Часы по ролям — это и есть смысл планера.
2. **Спринт — это несколько составов, а не один список.** У каждой роли свой состав, свой ресурс, свой остаток и свой перелимит. Согласовывать состав можно по одной роли, не дожидаясь остальных.
3. **Ёмкость считается, а не вводится «по ощущению».** Календарь, отсутствия, коэффициент грейда, доля участия — три модели описаны в главе 03.
4. **Планер ничего не хранит о задачах.** Оценки, факт, состояния, исполнители живут в YouTrack. Планер их читает, а записывает в задачу только исполнителя и значение спринта — и только по явной настройке.
5. **Закрытие спринта не переносит задачи.** Незакрытые задачи остаются в трекере как есть; на следующем планировании бэклог покажет их с меткой «Перенос». Решение — за командой, не за кнопкой.

## Чего нет

- Story points, burndown-график, доска с перетаскиванием карточек — доски остаются в YouTrack.
- Создание задач из планера — задачи заводятся в трекере.
